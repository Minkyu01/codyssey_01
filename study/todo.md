1. 절대경로는 루트(/) 에서 부터 파일의 위치를 찾는것, 상대경로는 현재 위치에서 다른 파일의 경로를 찾는것
예시는 pwd로 / 에서 현재 경로 보여주기, 
`mkdir -p `  상위 디렉토리까지 같이 만들기


2. 파일 권한

```
drwxr-xr-x@ 5 myu  staff  160  7월 24 14:03 piscine
-rw-r--r--@ 1 myu  staff    0  7월 24 14:03 test
```
맨 앞에 default : 일반 파일, d - directory, l 은 심볼릭 링크
심볼릭 링크 : 다른 파일이나 directory의 경로를 가리키는 파일 
-> 윈도우의 바로가기와 비슷함
`ln - s`

나머지 9개는 3개씩 나눠서 소유자, 소유 그룹, 기타 사용자의 권한을 나타냄

r(4), w(2), x(1)의 의미 , -(0)
r : read, 읽기 
w : write, 수정
x : 파일 실행
- : 해당 권한 없음 

```
- | rw- | r-- | r--
    소유자  그룹  기타 사용자 
```

권한 변경 명령어 : chmod + 숫자
키고 싶은 권한들의 합을 뒤에 적으면 됨
ex: chmod 755 test.txt

질문 : 내가 chmod 000으로 바꿨어, 그럼 권한이 없어지는 거냐
-> 읽기, 쓰기, 실행 권한은 사라짐, 그런데 난 파일 소유자 `myu` , chmod는 파일소유가자 파일 권한을 변경하는것

```
chmod u+x script.sh    # 소유자에게 실행 권한 추가
chmod a+r note.txt     # 모든 사용자에게 읽기 권한 추가
chmod o-r secret.txt   # 기타 사용자의 읽기 권한 제거
chmod u=rw note.txt    # 소유자 권한을 읽기·쓰기로 설정
```
기호의 의미:
u: 소유자
g: 그룹
o: 기타 사용자
a: 모든 사용자
+: 권한 추가
-: 권한 제거
=: 권한을 정확히 지정



3. 도커
맥, 리눅스, 윈도우처럼 각각 개발 환경이 제각각이기 때문에 가상의 환경을 만들어서 어떤 운영체제이든지 간에 같은 결과를 볼수 있게 해주는 기술

도커 이미지와 도커 컨테이너
- 도커 파일 : 설계도, 원하는 가상환경에 대한 정보들 적기
- 도커 이미지 : 도커파일을 `빌드` 해서 나온 결과물
    - 실행중인 프로그램 아님, 실행에 필요한 파일들과 설정들을 저장함
    - 이때 저장하는 방식을 레이어처럼 층으로 쌓음 -> 그래서 이미지를 수정하면 전체를 지우는게 아니라 각 층을 갈아끼우는 방식 -> 기존 레이어 재사용, 공유 가능
    - 각 레이어는 읽기 전용 + 실행중 생성 수정된 쓰기 가능 레이어
    `docker build -t workstation-web:1.0 .`
- 그렇게 가상화된 공간을 도커 컨테이너라고 함

``` text 
FROM nginx:1.27.5-alpine

COPY nginx/default.conf /etc/nginx/conf.d/default.conf
COPY site/ /usr/share/nginx/html/

RUN mkdir -p /usr/share/nginx/html/data

┌─────────────────────────────────────────┐
│ Layer 4: data 디렉터리 생성             │
├─────────────────────────────────────────┤
│ Layer 3: site 디렉터리 복사             │
├─────────────────────────────────────────┤
│ Layer 2: NGINX 설정 파일 복사           │
├─────────────────────────────────────────┤
│ Layer 1: nginx:1.27.5-alpine 기본 이미지│
└─────────────────────────────────────────┘
```

- 아래처럼 RUN으로 지우면 실제 컨테이너에선 파일이 지워지지만 이미지의 용량 자체는 그대로임
    - 그래서 실제 도커 이미지의 용량을 줄이려면 하나의 레이어에서 처리 해야함ㄴ
```
RUN curl -o big-file.zip https://example.com/big-file.zip
RUN rm big-file.zip

Layer 2: big-file.zip을 보이지 않게 함
Layer 1: big-file.zip 실제 데이터가 여전히 존재
```

- 이렇게 하나의 레이어에서 설치 + 삭제까지 해야지 실제 
```
RUN curl -o /tmp/big-file.zip https://example.com/big-file.zip \
    && unzip /tmp/big-file.zip \
    && rm /tmp/big-file.zip
```

도커 컨테이너 과정
- 실제 생성된 실행 프로그램(인스턴스)
- docker run으로 실행 -> 로컬에 저장된 이미지 없다면 Registry에서 이미지 다운로드
- 이미지 레이어 + 쓰기 가능한 컨테이너 추가 
- 네트워크, 포트 설정
- `볼륨과 바인드 마운트 연결`
- 프로세스 격리 , Entrypoint, cmd로 주 프로세스 실행 


- 이미지 하나로 여러 컨테이너 만들기 가능 
``` text 
              ┌─ container-A + 쓰기 레이어 A
image:1.0 ────┼─ container-B + 쓰기 레이어 B
              └─ container-C + 쓰기 레이어 C
```

- 외부 데이터 저장 방법
    - 컨테이너 밖에서 유지하고 싶은 데이터들을 연결

- 포트 매핑
    - 각 컨테이너는 별도의 네트워크 공간을 가짐 -> 그래서 호스트와 포트 매핑을 해줘야함


```text
Dockerfile + site + nginx config
              │ docker build
              ▼
      workstation-web:1.0 이미지
              │ docker run
       ┌──────┴──────┐
       ▼             ▼
 컨테이너 A      컨테이너 B
 host:8080       host:8081
```

## 바인드 마운트와 볼륨

두 방식 모두 컨테이너 외부의 저장 공간을 연결하지만 소유 주체와 용도가 다릅니다.

| 기준 | 바인드 마운트 | Docker 볼륨 |
|---|---|---|
| 지정 방식 | 호스트 경로 | 볼륨 이름 |
| 관리 주체 | 사용자와 호스트 OS | Docker |
| 주요 용도 | 소스코드·설정의 즉시 반영 | DB·업로드 등 영속 데이터 |
| 호스트 경로 의존성 | 높음 | 낮음 |
| 백업·이동 | 파일 도구 사용 | Docker 볼륨 절차 사용 |
